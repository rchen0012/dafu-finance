# DAFU 财务催款中心

## 启动演示

1. 解压项目，打开解压后含有 `server.mjs` 的 DAFU 目录。
2. 安装 Node.js 22 LTS（22.9 或更新版本），在该目录打开 PowerShell，运行：

   ```powershell
   node --env-file-if-exists=.env server.mjs
   ```

3. 浏览器打开 **http://127.0.0.1:3000**。默认进入演示模式，使用随当前日期滚动的示例账单，无需 Lark 凭证或安装项目依赖。按 Ctrl+C 停止服务。端口占用时，将 `.env.example` 复制为 `.env` 并修改 `PORT` 后重启。

## 接入实际 Lark Base

1. 在 Lark 开发者后台创建企业自建应用，申请 Base 的「查看、评论及导出多维表格」权限（`bitable:app:readonly`），发布并完成组织要求的审批。将应用加入目标 Base 的协作范围，并确认应用能读取目标表和所需字段。使用飞书时将 `LARK_REGION` 改为 `feishu`。
2. 在项目目录运行 `Copy-Item .env.example .env`。用文本编辑器打开 `.env`，填写：

   | 变量 | 用途 |
   | --- | --- |
   | MODE | 改为 `lark` |
   | DAFU_USER / DAFU_PASSWORD | 网页登录账号和至少 16 个字符的独立强密码 |
   | LARK_APP_ID / LARK_APP_SECRET | 自建应用凭证，填写在服务端环境变量 |
   | LARK_BASE_TOKEN | Base 的实际 `app_token`，通常来自原生 Base 链接的 `/base/` 段；Wiki 链接需先找到底层 Base |
   | LARK_TABLE_ID | 表 ID，通常来自链接的 `table=tbl…` |
   | LARK_VIEW_ID | 可选，填写时仅统计该视图返回的记录；汇总全表时留空 |
   | BUSINESS_TIME_ZONE / CURRENCY | 默认巴西圣保罗时区和 BRL；请按账簿实际口径修改。全表使用同一币种，不换汇 |

3. `config.json` 预设截图中的 22 个字段。左侧是 DAFU 账单详情标签，右侧是 Lark 的实际字段名。字段被改名时，只修改右侧值并重启。确实不存在的可选展示字段可设为 `null`。请保留并核对「客户名字」「剩余货款」以及用于计算到期日的字段。
4. 重启服务，刷新网页并登录。核对几笔账单的单号、剩余货款和到期日，再查看汇总。页面显示读取错误时，可按错误中的字段名核对映射，或检查应用发布状态、API 权限、Base 协作权限和表 ID。正式模式读取失败时页面显示错误。
5. 在「客户汇总 → 配置客户与门店」创建稳定的客户编号，选 A/B/C/D，填写信用额度及门店别名。每行一个别名，内容应与签单表「客户名字」中的对应门店一致。同一客户的多个门店共用额度和催款历史。

[官方 Base API 与协作权限说明](https://open.larksuite.com/document/server-docs/docs/bitable-v1/bitable-overview)

## 统计和放货口径

- 优先使用 Lark「到期日」和「剩余货款」。没有可识别到期日时，按开单日期加原表有效账期计算，账期未填写或无效时默认 60 个自然日。余额缺失进入待核对，不自动当成已结清。
- 应收余额汇总正的剩余货款。累计回款汇总两次还款金额。账单以 Lark 记录 ID 区分，重复单号仍分别展示。附件字段展示文件名。
- 催款任务按客户归并，包含逾期、今日到期或未来 7 天内到期的未收账单。点客户名可查看其所有未结清账单和催款历史，记录负责人、反馈及承诺付款日。
- 余额达到额度或有一笔账单逾期达到 30 天，显示「暂停放货」。达到预警线、普通逾期、未配置客户或数据待核对时显示「人工复核」。默认预警线是额度的 80%。等级和额度由财务配置。放货页面提供风险建议，实际审批和出库由业务人员执行。
- 可在 `config.json` 调整默认账期、催款提前天数、严重逾期天数和默认预警比例。

## 数据保存和权限

- 服务默认只监听本机。真实账单由服务端使用 Lark 应用凭证按页读取，token 在内存中缓存；账单表请求只有 GET。网页登录密码与 Lark App Secret 分开。请勿将 `.env` 或 `data/` 共享或提交到代码库。
- 门店配置和催款记录保存到 `data/demo-workflow.json` 或 `data/lark-workflow.json`，请按需备份。以单进程运行；网页首次保存配置后以对应工作流文件为准。更换客户编号会改变历史记录的归属键。
- 此包未启用机器人通知。未来如需发消息，要单独启用机器人并申请相应消息发送权限，同时确认机器人可在目标会话发言。Base 只读权限不包含发消息权限。


## 顾客管理与 Lark 写入

DAFU 的「顾客管理」支持新增和编辑顾客。演示模式保存在本机，正式模式在配置顾客表后直接写入 Lark。账单原表的 API 仍只读，催款反馈仍存本机。

1. 在 Lark Base 准备一张独立的「顾客档案」数据表。已有顾客表也可以复用，字段名称不同可在 `config.json` 的 `customerFields` 中按 `id,name,grade,limit,warning,aliases` 映射。配置示例：`"customerFields": {"name": "客户名称"}`。
2. 默认字段如下。每条顾客记录的编号必须唯一，每个门店别名只能属于一个顾客。别名应与账单表「客户名字」一致。

   | 字段 | Lark 字段类型 |
   | --- | --- |
   | 顾客编号 | 文本，可作为主字段 |
   | 顾客名称 | 文本 |
   | 等级 | 文本，填 A / B / C / D |
   | 信用额度 | 数字 |
   | 预警金额 | 数字，可留空 |
   | 门店别名 | 文本，每行一个别名 |

3. 在服务端 `.env` 设置 `MODE=lark` 和原有账单配置，再填 `LARK_CUSTOMER_TABLE_ID`。顾客表若在另一个 Base 中，请填 `LARK_CUSTOMER_BASE_TOKEN`。可用 `LARK_CUSTOMER_APP_ID`、`LARK_CUSTOMER_APP_SECRET` 给顾客表配置单独的应用。未填时沿用账单应用凭证。两项凭证应成对填写。
4. 顾客写入应用需要 Lark Base 的记录编辑权限和顾客表编辑权限。可用独立应用或独立 Base 限制其访问范围。账单应用可继续使用原只读权限。重启后打开「顾客管理」，列表会标明写入目标。
5. 启用顾客表后，顾客汇总和放货风险按 Lark 顾客表计算。原本机顾客配置需自行录入或导入顾客表。保留原顾客编号可继续关联 DAFU 催款历史。列表提示资料需核对时，请检查重复编号、重复门店或未填必填项。

GitHub Pages 是公开静态演示。操作真实顾客表请访问运行 DAFU Node.js 后端的受保护地址。线上部署应通过 HTTPS 反向代理访问后端，凭证只填在服务端。
